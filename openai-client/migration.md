# Migrating from gemini-client-api

`open-client` has the same structure as [gemini-client-api](https://crates.io/crates/gemini-client-api) 7.x: the same `Session`, `OverflowHandler`, `Chat` / `Part` / `PartType`, `MarkdownToParts`, `ask` / `ask_as_stream` / `ask_as_stream_with_extractor`, macros and features. Most code migrates by renaming. This document lists every difference in the public API, most of them coming from the OpenAI specification.

## Renames

| gemini-client-api | open-client |
|---|---|
| `gemini_client_api::gemini::*` | `open_client::openai::*` |
| `Gemini` | `OpenAI` |
| `GeminiEmbedding` | `OpenAIEmbedding` |
| `GeminiResponse` | `OpenAIResponse` |
| `GeminiResponseStream` | `OpenAIResponseStream` |
| `GeminiResponseError` | `OpenAIResponseError` |
| `GeminiResponseStreamError` | `OpenAIResponseStreamError` |
| `GeminiError` | `OpenAIError` |
| `GeminiSchema`, `gemini_schema()` | `OpenAISchema`, `openai_schema()` |
| `#[gemini_schema]`, `#[gemini_function]` | `#[openai_schema]`, `#[openai_function]` |
| `Role::Model` | `Role::Assistant` |
| `Role::Function` | `Role::Tool` |
| `Candidate` | `Choice` |

## Client (`OpenAI`)

- **New:** `set_base_url(url)` to use any OpenAI compatible API. Requests go to `{base_url}/chat/completions`. Default is `DEFAULT_BASE_URL` (`https://api.openai.com/v1`), and it has a `base_url()` getter.
- **New:** `OpenAI::from_env(model, sys_prompt)` reads `OPENAI_API_KEY` (required, else `Err(EnvVarError)`) and `OPENAI_BASE_URL` (optional), like the official OpenAI SDKs. `OpenAIEmbedding::from_env(model)` too.
- **New:** `OpenAI::with_no_api_key(model, sys_prompt)` sends no `Authorization` header, for local servers like Ollama. `OpenAIEmbedding::with_no_api_key(model)` too.
- `new_with_timeout()` (deprecated) is removed. Use `new_with_client()` with `reqwest::Client::builder().timeout(..)`. The same works for servers needing extra headers.
- `set_generation_config()` entries are added to the **top level** of the request body (`temperature`, `max_completion_tokens`, `seed`, `parallel_tool_calls`, provider specific ones...), as OpenAI has no `generationConfig` object. `model`, `messages`, `tools`, `tool_choice` and `stream` are ignored there.
- `set_thinking_config(ThinkingConfig)` becomes `set_reasoning_effort(ReasoningEffort)`. `ThinkingConfig`, `ThinkingLevel` and `ThinkingControl` are removed.
- **New:** `set_send_reasoning(bool)` sends thoughts back as `reasoning_content` in the ongoing tool calling loop, as DeepSeek requires. Off by default, as OpenAI rejects it.
- `set_tool_config(ToolConfig)` becomes `set_tool_choice(ToolChoice)` with `None`, `Auto`, `Required` and `Function(name)`. `ToolConfig`, `FunctionCallingConfig` and `FunctionCallingMode` are removed.
- `set_safety_settings()` is removed along with `SafetySetting`, `HarmCategory` and `BlockThreshold`. These don't exist in the OpenAI specification.
- Context caching is removed: `set_cached_content()`, `remove_cached_content()`, `create_cache()`, `list_caches()`, `get_cache()`, `update_cache()`, `delete_cache()` and `types::caching`. OpenAI caches prompts automatically. `prompt_cache_key` can be set in the generation config.
- `set_json_mode(schema)` sends `{"type": "json_schema", "json_schema": {"name": "response", "strict": true, "schema": schema}}`. Hand-written schemas must be [strict compatible](https://platform.openai.com/docs/guides/structured-outputs#supported-schemas): `"additionalProperties": false` and every property in `required`. `#[openai_schema]` does this for you.

### Tools

`Tool::FunctionDeclarations(Vec<Value>)` holding many functions becomes one `Tool::Function(Value)` per function, as each OpenAI tool is one function. `Tool::GoogleSearch`, `Tool::CodeExecution` and `Tool::UrlContext` become `Tool::Custom(Value)`, which is sent as it is for any provider specific tool.

**New:** `set_tool(tool)` adds one tool and replaces an existing function with the same name. `set_tools(vec)` still replaces all tools.

```rust
// Before
.set_tools(vec![Tool::FunctionDeclarations(vec![
    add_numbers::gemini_schema(),
    get_temperature::gemini_schema(),
])])
// Now
.set_tool(Tool::Function(add_numbers::openai_schema()))
.set_tool(Tool::Function(get_temperature::openai_schema()))
```

## Function calls and responses

OpenAI matches each function response to its call by id, so two parallel calls of the same function can be told apart.

- `FunctionCall` has an `id()`. `arguments()` is the raw JSON string, as generated by the model and streamed in pieces. `args()` parses it and returns `Result<Value, serde_json::Error>` instead of `&Option<Value>`. The constructor is `FunctionCall::new(id, name, args: Value)`, and `dissolve()` returns `(id, name, arguments)`.
- `session.add_function_response(name, response)` becomes `session.add_function_response(call_id, response)`. The name is taken from the call.
- `response` accepts anything `Serialize` as before (`IntoFunctionResponse`). Strings are sent as they are and everything else as JSON text. Values are no longer wrapped in `{"result": ..}`.
- **New:** `MultimodalResponse` responds with images, audio or files, e.g. a screenshot. These can't be in a `tool` message per the OpenAI specification, so they are sent in a `user` message right after the tool messages.
- `FunctionResponse` is `FunctionResponse::new(id, name, parts: Vec<Part>)` with `parts()`, instead of `response: Value`.
- **New:** `AddFunctionResponseError::NoPendingCall(id)` is returned if the last reply has no unanswered call with that id.
- **New:** `session.get_pending_function_calls()` returns the unanswered calls of the last reply.

```rust
// Before
session.add_function_response(call.name(), result)?;
// Now
session.add_function_response(call.id(), result)?;
session.add_function_response(call.id(), MultimodalResponse::new(vec![
    "Screenshot".into(),
    InlineData::from_path("screen.png", mime::IMAGE_PNG).await?.into(),
]))?;
```

## Types

- `PartType::ExecutableCode`, `PartType::CodeExecutionResult` and `PartType::FileData` are removed along with `ExecutableCode`, `CodeExecutionResult`, `FileData`, `Language` and `Outcome`.
- **New:** `PartType::ImageUrl(ImageUrl)`, an image the API server fetches by URL (with optional `ImageDetail`).
- **New:** `PartType::Refusal(String)`, with `Chat::get_refusal()`.
- `InlineData` is unchanged. It's sent as `image_url` (data URL) for `image/*`, as `input_audio` for `audio/*`, and as `file` for anything else, e.g. PDF.
- `Part` has no `thought_signature`. Thoughts are `Text` parts with `thought: true`, received from `reasoning_content` or `reasoning`. **New:** `Part::new_thought(text)`.
- Text-only messages are sent as a plain string, so servers like DeepSeek that don't accept content parts still work.
- Sessions saved by gemini-client-api can't be loaded, as roles and parts differ.

## Responses

- `GeminiResponse { candidates, usage_metadata, model_version, prompt_feedback, response_id, model_status }` becomes `OpenAIResponse { id, model, choices, usage, extra }`. `extra` holds every other field, e.g. `created` or provider specific `citations`.
- `Choice { index, message, finish_reason, logprobs }` replaces `Candidate { content, finish_reason }`.
- `FinishReason` variants are now `Stop`, `Length`, `ToolCalls`, `ContentFilter`, `FunctionCall` and `Other` (for any unknown reason).
- `get_chat()` returns an empty reply instead of panicking when there is no choice, e.g. in the last streamed chunk that only has `usage`.
- `get_json()` / `parse_json()` ignore thoughts and a surrounding markdown code fence.
- Streaming: each item has only the newly received part of the reply. Function call arguments arrive in pieces and are assembled in the session, so read complete calls from `session.get_last_chat()` / `response_stream.get_session()`. As in the official OpenAI SDKs, pieces of a call are matched by `index`, keeping the first `id` and `name`. A call without `index` is complete, e.g. from Gemini. Token usage needs `stream_options: {"include_usage": true}` in the generation config.

## Errors

- `GeminiResponseError::StatusNotOk(GeminiError { error: Error { code, message, status: Status, details } })` becomes `OpenAIResponseError::StatusNotOk(OpenAIError { status: StatusCode, error: ApiError { message, type, param, code } })`. Servers differ in error format, so it's parsed leniently, and the `Status` enum is removed. Use the HTTP `status`.
- **New:** `OpenAIResponseError::InvalidResponseFormat(String)` for a response not matching the specification. It includes the body.
- `GeminiResponseStreamError::InvalidResposeFormat` is renamed to `OpenAIResponseStreamError::InvalidResponseFormat` (typo fixed).
- **New:** `OpenAIResponseStreamError::ApiError(ApiError)` for an error event received mid-stream.

## Embeddings

| gemini-client-api | open-client |
|---|---|
| `GeminiEmbedding::new(key, model)` | `OpenAIEmbedding::new(key, model)`, **new** `set_base_url()` |
| `set_output_dimensionality(n)` | `set_dimensions(n)` |
| `set_task_type()`, `set_config()`, `TaskType`, `EmbedContentConfig`, `Content` | Removed. Not in the OpenAI specification |
| `embed(Vec<Part>)`, one embedding of all parts | `embed_texts(Vec<String>)`, one embedding per text |
| `embed_text(text)` | `embed_text(text)` |
| `EmbedContentResponse`, `embedding()` | `EmbeddingResponse`, `embedding()` (first), `embeddings()` (all) |
| `ContentEmbedding` | `Embedding`, with `index()` |

## Removed helpers

Helpers that were public in gemini-client-api are private, and APIs it deprecated or replaced are left out.

- `GeminiRequestBody` and `concatenate_parts()` are private.
- The `utils` module (`get_file_base64s()`, `MatchedFiles`) is private. `mime` is re-exported at the crate root (`open_client::mime`), and `utils::{HeaderMap, HeaderValue}` are replaced by the re-exported `open_client::reqwest`.
- `MarkdownToParts::new()`, `new_checked()`, `from_regex()` and `from_regex_checked()` are removed. Use `MarkdownToParts::builder()`, which has all their options. `MarkdownToParts` has no getters or `dissolve()`, and needs the `reqwest` feature.
- The deprecated `Session::get_parts()`, `get_parts_mut()`, `get_parts_no()` and `get_parts_no_mut()` are removed. Use `get_previous_chat()`, `get_previous_chat_mut()` and `get_history_as_vecdeque()`.
- `GeminiSchema::name(&schema)` is removed. Use `Tool::name()`.

## Macros

- Generated schemas are standard JSON Schema in lowercase (`"object"`, `"string"`...). They're strict-mode compatible: objects have `"additionalProperties": false`, and **every** field is `required`. `Option<T>` is nullable (`{"type": ["string", "null"]}`, or `anyOf` with `{"type": "null"}` for non-primitive types) instead of `"nullable": true` and not required. Optional arguments still parse when the model omits them.
- A function without doc comments has no `"description"` in its schema, instead of an empty one.
- `execute_function_calls!` and `execute_function_calls_with_callback!` handle the pending calls of the last reply (`session.get_pending_function_calls()`), so calls you've already answered manually are skipped. If the same function is called more than once, every call runs. The returned vector still has one slot per function, holding the last result.
- Invalid JSON arguments are reported as the `Err` result of that call, instead of panicking.
- The callback of `execute_function_calls_with_callback!` can return anything accepted by `add_function_response()`, e.g. `MultimodalResponse`.
- Generated code uses fully qualified `::open_client::..` paths. Your crate doesn't need `serde` / `serde_json` dependencies for the macros, and `OpenAISchema` only needs importing to call `openai_schema()`.
- `#[openai_function]` no longer generates a public `<function>_args` struct. The generated `<function>` struct (holding `openai_schema()`, `execute()` and `parse_arguments()`) has the visibility of the function instead of always `pub`.
- Unsupported input (e.g. tuple structs, enums with data, destructured arguments) is a compile error pointing at it, instead of a panic.
